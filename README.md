# Система учёта заявок

Учебный проект по дисциплине «Технологии разработки программного обеспечения».

Автор: **Привалов М.Ф., ИСИП-407**

## Назначение

Система предназначена для регистрации, обработки, распределения и контроля заявок.

## Роли пользователей

- **Администратор** — управление пользователями и настройками.
- **Оператор** — регистрация и обработка заявок.
- **Исполнитель** — выполнение назначенных заявок.
- **Заявитель** — создание заявок и просмотр их статуса.

## Реализовано в лабораторной работе №6

- создание, просмотр и редактирование заявок;
- поиск по теме, описанию и имени заявителя;
- фильтрация по статусу и категории;
- изменение статуса заявки;
- проверка входных данных и связанных сущностей;
- SQLite и воспроизводимые демонстрационные данные: 10 заявок, 5 пользователей, 4 категории и 4 статуса;
- базовый веб-интерфейс и автоматические тесты.

## Структура

```text
docs/              документация, журнал ИИ и чек-лист
src/models.py      модели и проверка данных

tests/             автоматические проверки
```

## Запуск в Windows PowerShell

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
uvicorn src.main:app --reload
```

Откройте `http://127.0.0.1:8000/`. Документация HTTP-маршрутов доступна по адресу `http://127.0.0.1:8000/docs`, проверка состояния — `http://127.0.0.1:8000/health`.

При первом старте создаётся локальная база `data/requests.sqlite3`. Для другого пути задайте переменную окружения `REQUESTS_DB_PATH`. Локальная база исключена из Git; тестовые данные создаются кодом и также описаны SQL-скриптами.

## REST API — лабораторная работа №7

API реализовано на FastAPI поверх сервисного слоя лабораторной №6.

### Документация

После запуска приложения откройте Swagger UI: `http://127.0.0.1:8000/docs`. OpenAPI JSON доступен по адресу `http://127.0.0.1:8000/openapi.json`.

### Основные endpoints

| Метод | Путь | Назначение | Основные ответы |
|---|---|---|---|
| GET | `/requests` | Список заявок | 200, 422 |
| GET | `/requests/{request_id}` | Одна заявка | 200, 404 |
| POST | `/requests` | Создание | 201, 400, 422 |
| PATCH | `/requests/{request_id}` | Частичное редактирование | 200, 400, 404, 422 |
| PATCH | `/requests/{request_id}/status` | Смена статуса | 200, 400, 404, 422 |
| DELETE | `/requests/{request_id}` | Удаление | 204, 404 |
| GET | `/users` | Список пользователей | 200 |
| GET | `/statuses` | Справочник статусов | 200 |
| GET | `/categories` | Справочник категорий | 200 |
| GET | `/health` | Проверка доступности | 200 |

Параметры списка заявок: `search` — поиск по теме, описанию и имени заявителя; `status_id` — фильтр по статусу; `category_id` — фильтр по категории.

### Пример создания заявки

```http
POST /requests
Content-Type: application/json

{
  "title": "Не работает принтер",
  "description": "Принтер не реагирует на отправку документов",
  "user_id": 1,
  "category_id": 1,
  "assignee_id": 3
}
```

Успешный запрос возвращает `201 Created` и JSON созданной заявки. Поля `title` и `description` валидируются; связанные пользователь и категория должны существовать.

### Проверка через Postman

Импортируйте коллекцию `postman/RequestSystem_Lab7.postman_collection.json`. Перед выполнением запустите сервер. Запускайте запросы сверху вниз: коллекция сохраняет ID созданной заявки в переменную `requestId` и использует его для получения, изменения, смены статуса и удаления.

### Автоматические проверки API

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

Тесты лабораторной №7 находятся в `tests/test_lab7.py`. Последний зафиксированный локальный запуск: `7 passed, 1 warning in 1.74s`. Предупреждение `StarletteDeprecationWarning` относится к интеграции `httpx` со `starlette.testclient` и не привело к падению тестов. Повторите тесты после получения последних изменений перед сдачей.
