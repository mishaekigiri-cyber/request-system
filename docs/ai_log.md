# Запись по лабораторной работе №7 — REST API

## Взаимодействие 1 — проектирование API-контракта

- **Этап:** анализ требований лабораторной работы №7.
- **Модель:** ChatGPT, GPT-6.
- **Первоначальный неполный запрос:** «Добавь API к проекту».
- **Недостатки:** не указаны HTTP-методы и пути; не заданы коды ошибок; не оговорены схемы JSON и query-параметры; не указаны требования к документации и коллекции запросов.
- **Уточнённый запрос:** «На основе существующего проекта FastAPI/SQLite составь REST-контракт для сущности Request. Сохрани существующие модели и сервисный слой; опиши методы GET списка и объекта, POST, PATCH, удаление, смену статуса, справочники, поиск/фильтры, схемы данных, HTTP-коды 200/201/204/400/404/422 и документацию OpenAPI. Не дублируй бизнес-логику в endpoints».
- **Контекст:** `src/main.py`, `src/models.py`, `src/services.py`, `src/database.py`, README и требования из методических указаний ЛР №7.
- **Результат:** сформирован список endpoints и правил валидации; принято использовать FastAPI и автоматически генерируемую OpenAPI-документацию.
- **Проверка:** сопоставление с таблицей обязательных endpoints в методических указаниях.
- **Почему выбран такой промпт:** он задаёт ограничения существующего проекта и позволяет проверять полноту API-контракта по требованиям.
- **Итог:** API строится поверх существующего сервисного слоя, без создания второго независимого слоя бизнес-логики.

## Взаимодействие 2 — ревью контракта и тестового покрытия

- **Этап:** реализация и ревью.
- **Модель:** ChatGPT, GPT-6.
- **Запрос:** «Проведи критическое ревью REST API системы учёта заявок. Проверь HTTP-коды, валидацию JSON, ошибки отсутствующей заявки и связанных сущностей, поиск и фильтрацию, DELETE, OpenAPI и возможность воспроизвести сценарий из Postman. Предложи минимум три риска и конкретные проверки. Не заявляй, что код протестирован, пока тесты не запускались».
- **Результат:** добавлены описания endpoints для Swagger UI, удаление заявки через сервисный слой, автоматические проверки контракта и коллекция Postman с последовательными запросами.
- **Проверка:** тесты подготовлены в `tests/test_lab7.py`; коллекция `postman/RequestSystem_Lab7.postman_collection.json` содержит 16 запросов с проверками ответов. Фактический локальный прогон новой коллекции и новых тестов ещё требуется выполнить.
- **Доработка:** DELETE использует ответ `204 No Content`; для отсутствующей записи ожидается `404`; ошибки схемы входных данных проверяются отдельно от бизнес-ошибок связанных сущностей.
- **Почему выбран такой промпт:** он направляет ревью на HTTP-контракт, обработку ошибок и воспроизводимость, а не только на внешний вид кода.
- **Фактическая локальная проверка (13.10.2026):** `python -m pytest -q` завершился результатом `4 passed, 1 warning in 0.60s`. Предупреждение `StarletteDeprecationWarning` касается использования `httpx` с `starlette.testclient`; оно не привело к падению тестов. В Swagger вручную проверены создание заявки (`201`), удаление (`204`), GET удалённой заявки (`404`), справочники и поиск без совпадений (`200`, `[]`), пустое название (`422`) и недопустимый исполнитель (`400`). Коллекция Postman отдельно не запускалась; её выполнение остаётся в чек-листе.
