Проект: **Система учёта заявок**

## Состав базы

Используется SQLite и пять таблиц:
- `Users` — пользователи и роли;
- `Requests` — заявки;
- `Statuses` — справочник статусов;
- `Categories` — справочник категорий;
- `Comments` — комментарии к заявкам.

Связи реализованы внешними ключами. Email пользователя и названия статусов/категорий уникальны. Роль пользователя ограничена допустимыми значениями.

## Файлы проекта

- `database/schema.sql` — создание таблиц и ограничений;
- `database/seed.sql` — тестовые данные;
- `database/queries.sql` — примеры SELECT, WHERE, JOIN и сгруппированных результатов;
- `database/dml_test.sql` — демонстрация двух UPDATE и двух DELETE с последующим ROLLBACK.

## Запуск

В SQLite CLI из корня репозитория выполните:

```sql
.read database/schema.sql
.read database/seed.sql
.read database/queries.sql
.read database/dml_test.sql
```

В DB Browser for SQLite откройте базу данных, перейдите в Execute SQL и выполните содержимое скриптов последовательно. Для чистого повторного запуска сначала выполните `schema.sql`, затем `seed.sql`.

## Проверки

В `queries.sql` представлены выборки всех заявок, фильтрация через `WHERE`, соединение таблиц через `JOIN`, подсчёт заявок по категориям через `GROUP BY` и вывод заявок вместе с категориями, статусами, заявителями и исполнителями.

Скрипт `dml_test.sql` выполняет два UPDATE и два DELETE внутри транзакции, а затем откатывает изменения. Это позволяет продемонстрировать команды изменения и удаления, не испортив исходные тестовые данные. Запускайте его после заполнения БД скриптом `seed.sql`.

## Иллюстрации

Иллюстрации результатов SQL в отчёте сохранены без изменений по просьбе автора. Это оформленные визуальные примеры результатов запросов, а не снимки экрана из DB Browser for SQLite. Если преподаватель требует именно скриншоты приложения, их нужно снять отдельно в DB Browser после выполнения запросов.

## Ограничения текущей модели

Модель предназначена для учебного прототипа и включает основные сущности учёта заявок. Отдельная таблица истории изменения статусов не реализована; текущий статус хранится в `Requests.status_id`.
